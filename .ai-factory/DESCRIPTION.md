# UI тренировок

## Обзор

Мобильный frontend для Telegram Mini App, работающий с Laravel API проекта `api-tren`. Пользователь авторизуется через Telegram `initData`, составляет недельное расписание тренировок, выполняет упражнения в произвольном порядке и просматривает историю завершённых или отменённых сессий.

Backend является источником истины для программ, активной сессии и истории. UI не подключается к PostgreSQL или Redis напрямую и взаимодействует с backend только через HTTP API.

## Основные возможности

- Аутентификация через проверяемый сервером `Telegram.WebApp.initData` и получение Bearer token.
- Просмотр недельного расписания и создание, редактирование или удаление тренировочной программы для выбранного дня.
- Запуск одной активной тренировочной сессии и восстановление её состояния после повторного открытия Mini App.
- Редактирование фактических подходов, завершение, пропуск и повторное открытие упражнения.
- Завершение или отмена тренировки после обработки всех упражнений.
- Просмотр cursor-based истории тренировок.
- Анализ завершённой тренировки: числовое сравнение плана и факта, готовое заключение и контекст истории.
- Применение или отклонение рекомендаций в истории и перед стартом; будущий план обновляется отдельно от исторических снимков.
- Адаптация темы, viewport, safe area и нативных элементов управления к окружению Telegram.

## Технологический стек

- **Язык программирования:** TypeScript
- **Framework:** Nuxt 4, Vue 3, Composition API, `<script setup>`
- **UI:** Nuxt UI 4 и Tailwind CSS
- **Получение данных:** Nuxt `useFetch`/`$fetch` с типизированным API client; отдельный store только для долгоживущего клиентского состояния
- **Telegram:** Telegram Mini Apps API/SDK
- **Тестирование:** Vitest, `@nuxt/test-utils`, Playwright
- **База данных:** отсутствует на frontend; PostgreSQL принадлежит backend
- **ORM:** не используется
- **Backend:** Laravel 13, Sanctum, PostgreSQL, Redis — отдельный репозиторий `stivz-division/api-tren`

## Интеграции

- `POST /api/auth` принимает сырой `init_data` Telegram и возвращает Bearer token.
- Защищённые `/api/training-programs*` управляют недельным расписанием.
- Защищённый `GET /api/exercises` возвращает production-каталог упражнений с `id` и `name`.
- Защищённые `/api/workout-sessions*` управляют активной тренировкой и cursor-based историей.
- Все изменяющие операции должны учитывать `409 Conflict`, а формы — отображать Laravel validation errors с кодом `422`.

## Архитектурные заметки

- Организовать frontend по предметным feature-модулям: аутентификация, расписание, выполнение тренировки и история.
- Изолировать детали `$fetch`, Bearer token и Laravel response envelopes в одном API adapter.
- Хранить server state через Nuxt data composables; не дублировать ответы API в глобальном store без необходимости.
- Telegram-specific вызовы выполнять только на client side и скрывать за адаптером, чтобы браузерные тесты могли использовать безопасную заглушку.
- Считать backend единственным владельцем переходов статусов и после mutation принимать возвращённую сессию как актуальное состояние.

## Нефункциональные требования

- **Mobile-first:** поддержка узкого viewport, safe-area insets, экранной клавиатуры и Telegram theme parameters.
- **Доступность:** семантическая разметка, заметный focus state, достаточный contrast и screen-reader announcements для асинхронных изменений.
- **Ошибки:** единая типизированная модель ошибок для `401`, `404`, `409`, `422`, `429` и сетевых сбоев.
- **Безопасность:** не доверять `initDataUnsafe`, передавать backend только сырой `initData`, не логировать `initData` и Bearer token.
- **Надёжность:** защищать mutation-кнопки от повторной отправки; для конфликтов не выполнять слепой автоматический retry.
- **Логирование:** диагностические сообщения без персональных данных и секретов, управляемые уровнем окружения.
- **Конфигурация:** base URL API задаётся через Nuxt runtime config и environment variables.
